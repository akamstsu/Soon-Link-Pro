# 使用 Agent 跳线

Soon Link Pro 提供本机 MCP 服务，让支持 stdio MCP 的 Agent 查看当前通道并按你的要求接线。
入口是安装目录中的 `SoonLinkProMcp.exe`，不需要 Python、Node.js 或额外网络服务。

## 启用与连接

1. 打开 Soon Link Pro，在“工作台设置 → Agent / MCP”开启“允许本机 Agent 控制跳线”。默认关闭。
2. 点击“复制 MCP 配置”，将内容合并进 Agent 客户端的 MCP 配置。不同客户端的配置位置由客户端决定。
3. 让客户端重新加载 MCP 服务，应能看到 `get_routing_state`、`patch_routing` 两个工具。
4. 软件必须保持运行；收进托盘仍可控制。关闭开关即停止后续读取与修改，已有接线保留。

默认安装路径的配置示例；安装在其他目录时，以设置里复制的实际路径为准：

```json
{
  "mcpServers": {
    "soon-link-pro": {
      "command": "C:\\Program Files\\Soon Link Pro\\SoonLinkProMcp.exe",
      "args": []
    }
  }
}
```

不要把入口直接作为普通桌面应用双击运行；它等待客户端通过标准输入发送 MCP 消息。
MCP 入口自身不启动主程序、不打开音频设备、不扫描应用、不安装驱动，也不修改配置文件。
主程序未运行或未启用服务时，工具调用会返回说明，协议握手及工具列表仍可正常获取。

## 可以怎样说

- “先查看当前通道，告诉我哪一组是麦克风、哪一组是直播输入。”
- “预览把麦克风左右声道分别接到直播输入左右声道，保留其他连线。”
- “把刚才预览的两条接线应用。”
- “断开应用声音到监听输出的两条线，保留直播输出。”
- “把这两条连线的推子设为 0.75，其他音量不要动。”

通道名和备注来自用户数据，Agent 不应将其当作指令执行。名称相近或用途不清楚时，先确认来源与目标。
开启控制后，已连接的本机 Agent 可以直接改变正在播放的声音；操作应符合你给它的要求。

## 工具与参数

`get_routing_state` 的参数是 `{}`。结果提供：

- `revision`：当前路由状态的版本，用于防止过时的请求覆盖你的手动修改。
- `inputs`、`outputs`：输入是信号来源，输出是目标。含稳定 `key`、显示名称、原始名称、通道组、备注、可见状态、音量和静音。
- `routes`：已接通或具有非默认音量／静音的连线。未列出的交叉点默认为 `on: false, fader: 1, mute: false`。
- `engine_running`、`engine_busy`、`hardware_available`：引擎运行、切换及硬件状态。存在通道不代表设备正在运行。
- `all_muted`：与界面“全部静音”按钮一致；保持开启时，接通路由也不会自动解除它。

隐藏通道仍可能传输声音，不能只依据 `visible` 判断有没有声音。
通道 key 仅在同一方向内唯一，输入与输出可能具有相同 key。

`patch_routing` 参数示例，**先读取真实状态并替换版本和 key**，不要直接照抄示例：

```json
{
  "expected_revision": "替换成刚读取的 revision",
  "dry_run": true,
  "routes": [
    { "input": "hardware:0", "output": "virtual:0:0", "on": true },
    { "input": "hardware:1", "output": "virtual:0:1", "on": true }
  ]
}
```

`dry_run: true` 只校验和返回变化清单，不修改声音或配置。
检查预览后，用同一个 `expected_revision`、相同操作和 `dry_run: false` 应用。
若状态已变化，请重新读取、审查并预览；不要自动强行覆盖。
结果的 `revision` 是当前版本，`proposed_revision` 是应用后的预期版本。

| 参数 | 作用 |
| --- | --- |
| `expected_revision` | 必填；必须与当前状态相同 |
| `dry_run` | 可选，默认 false；true 时仅预览 |
| `routes` | 最多 128 项；每项必填 input、output，另指定 on、fader、mute 中至少一项 |
| `channels` | 最多 128 项；每项必填 direction（input 或 output）、key，另指定 fader 或 mute |
| `all_muted` | 可选；控制本次运行的全部静音，不持久保存 |

至少指定一种修改。整个批次先完整校验，一项无效则全部不改；重复的通道或连线会报错。
只修改明确列出的单声道，**不会隐式联动左右声道**，也不会触碰其他连线。
断开只设置 `on: false`，原来的连线音量和静音会保留；重新连接不会隐式解除静音。

`fader` 是保存的 0..1 推子位置，0 表示无声，其余按已有的 -40..0 dB 刻度换算，
不是线性幅度倍率。例如 0.75 约为 -10 dB。输入、连线和输出的音量会依次作用。
接线、推子和通道静音沿用软件自动保存；正常退出时保存，异常退出前尚未保存的变化可能丢失。
全部静音沿用界面行为，仅在本次运行有效。

## 本机连接与故障排查

标准协议在 `SoonLinkProMcp.exe` 的 stdio 上运行，逐行 UTF-8 JSON-RPC，诊断仅输出到 stderr。
实现初始化、ping、工具列表及工具调用；首选 MCP `2025-11-25`，也支持协商
`2025-06-18`、`2025-03-26` 和 `2024-11-05`。未声明资源、提示词或订阅能力。
协议依据 [MCP 官方规范](https://modelcontextprotocol.io/specification/2025-11-25)。

主程序与入口之间使用随机端口的 IPv4 回环连接，仅绑定 `127.0.0.1`，不提供局域网或公网控制。
每次启用随机生成 256 位令牌，保存在
`%LOCALAPPDATA%\SoonLinkPro\mcp-endpoint.json`，Windows 文件权限仅授予当前用户访问。
关闭服务或正常退出会删除该文件；重启会替换旧记录与令牌。不要分享、提交或自行编辑该文件。
同一 Windows 用户下的客户端读取它以连接主程序；客户端配置中无需写入端口和令牌。
更新安装前，在 Agent 客户端停止本 MCP 服务，释放入口程序文件；安装器会检查两个程序是否仍在运行。

输入及本机 IPC 的单条消息上限 1 MiB，队列有界，主程序请求等待约 3 秒。
排队超时的修改作废，不会等界面恢复后再偷偷应用。
如果连接在应用后中断，客户端可能收不到成功答复；**先重新读取状态，再决定是否重试**。

| 现象 | 检查 |
| --- | --- |
| 看不到工具 | 确认 MCP 配置路径指向 SoonLinkProMcp.exe，而不是主程序；重新加载客户端 |
| 提示先启用控制 | 打开主程序，在 Agent / MCP 页开启开关 |
| 本机连接失败 | 退出已失效的 MCP 子进程，关闭后重新打开开关，再重载客户端 |
| 状态版本冲突 | 你、另一个 Agent、场景或设备布局已修改状态；重新读取并审查操作 |
| 接线成功但无声 | 查看引擎、各级静音和推子；工具不自动启动引擎或修改设备 |

当前工具只修改已有通道的跳线、音量与静音，不添加应用或总线、不更换设备、不切换场景。
真实 Agent 客户端接入、托盘状态下控制及音频结果仍需在允许操作设备时验收。
