## 实际分发时怎么做

- 分发源码：保留根目录 `LICENSE` 中的版权行和完整许可，以及所含第三方组件的适用声明。
- 分发 EXE、DLL、安装包或整合包：让接收者获得版权和完整许可文本，例如放在安装目录的
  `licenses` 文件夹；只链接到可能变化的网页不如随包提供文本可靠。
- 分发修改版：建议保留 `NOTICE`，并另行说明自己的修改与署名。不能通过改名或重新编译免除
  原有声明的保留义务。MIT 不强制采用特定文件名或专门的修改记录格式。
- 第三方组件：保留其各自要求的版权、完整许可及其他通知；本项目的 MIT 不能替代它们。

当前打包脚本已随包提供 `licenses/LICENSE`、`licenses/NOTICE`、第三方声明及完整许可。
本页是解释文档；保留义务来自相应许可，不是要求所有分发者额外附带本页。

## 版权声明和界面署名有什么区别

MIT 要求保留版权和许可声明，但没有指定必须在启动页、主界面或“关于”窗口展示作者姓名。
在随包保留必需声明、履行其他适用许可义务的前提下，MIT 允许修改界面及其中的署名展示。
不能把“界面没有署名”单独视为违反 MIT，也不能因界面有署名就省略随包许可文本。

代码许可不等于获得以原作者名义背书的许可；项目名、Logo 和其他商标的使用还受适用法律约束。
修改版应清楚区分其维护者，避免让用户误以为它获得本项目或第三方品牌的认可。

## 能不能增加额外约束

权利人可以在有权授权的范围内选择其他许可条件，但“界面必须永久显示指定署名”等新增强制条件
超出了标准 MIT。不能一边标注纯 MIT，一边通过 README 或 NOTICE 悄悄添加冲突条件。
当前项目继续使用标准 MIT，未附加禁止商用、强制开源或固定界面署名的限制。

若以后改变许可，需要明确适用版本、检查贡献与依赖的授权范围，并同步更新许可文件和说明。
新条件不会仅凭更新仓库文件就追溯约束已经按 MIT 获得的旧版副本。
保留版权声明这一现有要求已经覆盖“允许使用，但不能删掉随副本附带的版权与许可信息”的目标。
